# Contributing to Stock-Price-Predictor

Thank you for considering contributing to Stock-Price-Predictor! This document provides guidelines for contributing to this project.

## Getting Started

1. Fork the repository
2. Clone your fork to your local machine
3. Create a new branch for your contribution with an appropriate prefix:
   - Use `feature/` for new features (e.g., `feature/add-prophet-model`)
   - Use `fix/` for bug fixes (e.g., `fix/data-loading-issue`)
   - Use `docs/` for documentation changes (e.g., `docs/update-installation-guide`)
   - Use `refactor/` for code refactoring (e.g., `refactor/prediction-algorithm`)
   - Use `test/` for adding or updating tests (e.g., `test/model-accuracy`)
4. Set up the development environment as described in the README.md

## How to Contribute

### Code Contributions

1. Ensure your code follows the project's style guidelines
2. Add or update tests as necessary
3. Update documentation to reflect your changes
4. Verify that your changes don't break existing functionality

### Areas for Contribution

- Implementing additional machine learning models
- Enhancing data preprocessing techniques
- Improving visualization of predictions
- Adding support for additional stocks/companies
- Optimizing the existing algorithms
- Improving documentation

## Pull Request Process

1. Update the README.md with details of changes if applicable
2. Ensure your code passes all tests
3. Submit a pull request with a clear description of the changes
4. Link any relevant issues in your pull request

## Branch Naming Convention

To keep the repository organized, please follow these branch naming conventions:

- `feature/brief-description` - For new features
- `fix/brief-description` - For bug fixes
- `docs/brief-description` - For documentation changes
- `refactor/brief-description` - For code refactoring
- `test/brief-description` - For adding or updating tests

Examples:
- `feature/add-lstm-model`
- `fix/prediction-accuracy-issue`
- `docs/add-usage-examples`
- `refactor/optimize-data-processing`
- `test/add-model-validation`

## Code Style Guidelines

- Follow PEP 8 style guidelines for Python code
- Use meaningful variable and function names
- Include docstrings for functions and classes
- Comment complex sections of code

## Reporting Issues

When reporting issues, please include:

- A clear and descriptive title
- Detailed steps to reproduce the issue
- Expected and actual behavior
- Screenshots if applicable
- Your environment information (OS, Python version, etc.)

## Dataset Guidelines

If you're contributing modifications to the dataset or adding new datasets:

1. Ensure data is properly cited with its source
2. Document any preprocessing steps applied to the data
3. Verify that the data format is consistent with the existing dataset

## Questions or Suggestions?

If you have questions or suggestions about contributing, please open an issue with the tag "question" or "suggestion".

Thank you for your interest in improving Stock-Price-Predictor!
